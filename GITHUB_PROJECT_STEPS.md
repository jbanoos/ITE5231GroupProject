# GitHub Projects: Agile Board Evidence Steps

- Create a GitHub repository for the project and push the initial code so issues can be linked to commits later.
- Open the repository on GitHub, click the Projects tab, and click "Link a project" or go to your profile's Projects page and click "New project".
- Choose the "Board" template (or "Team backlog") so the project starts with a kanban-style board view.
- Name the project, for example "Hospital Patient Management System", and add a short description referencing the assignment.
- Open the project Settings and add an "Iteration" field; create iterations named Sprint 1 and Sprint 2 with start dates and one- or two-week lengths.
- Edit the Status field so it has at least three columns: To do, In progress, and Done.
- Add custom fields useful for evidence: Priority (single select: High/Medium/Low) and Estimate (number, story points or hours).
- Create a GitHub issue for each assignment requirement, for example: Patient model, PatientRegistry with Dictionary, sorted-linked-list TriageQueue, per-doctor Stack of appointments, MedicalHistory linked list, MedicalHistoryIterator, Singleton HospitalSystem, Observer notifications, Strategy billing, console workflow, unit tests, and final report.
- Write a short description and acceptance criteria in each issue so the board cards are self-explanatory.
- Add each issue to the project from the issue page sidebar ("Projects" section) or from the board using "+ Add item".
- Drag each card into the correct Status column (start with everything in To do).
- Assign each card to yourself (or team members) using the Assignees field.
- Set Priority and Estimate on every card so the board shows estimation and prioritization evidence.
- Assign cards to Sprint 1 or Sprint 2 using the Iteration field, matching the two-phase plan.
- Create a Sprint view: click "+ New view", choose Board, group by Iteration, and save it as "Sprint view".
- Create a Table view grouped by Status or Priority for a backlog overview.
- When starting work on a card, move it from To do to In progress.
- In every commit message, reference the issue number (for example "Add TriageQueue sorted linked list (#3)") so commits appear linked on the issue.
- Open pull requests that reference issues with "Closes #N" so merging the PR automatically closes the issue and moves the card to Done.
- Verify each card ends in Done only after its code builds and its tests pass.
- Take screenshots throughout: the full board mid-sprint, an issue with linked commits/PRs, the sprint view grouped by iteration, and the fields showing Priority/Estimate.
- Capture the Project Insights (burnup chart) page as additional sprint-progress evidence.
- Do not delete completed cards, issues, or iterations; the closed issues and card history are the Agile process evidence.
- At the end, take a final screenshot of the board with all cards in Done and include the screenshots plus the project URL in the report.
